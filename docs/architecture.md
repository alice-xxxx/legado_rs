# 架构与产品约定

本文件是项目的稳定约定。

## 产品范围

- Android、iOS、Windows、macOS、Linux 统一推进。
- **本 App 尚未发布，无须迁移内部旧格式**：书架、进度、设置、备份及旧式 HTML 章节缓存等过时的本应用内部格式可以直接删除兼容分支、旧读写实现和死代码。这条规则不适用于 Legado 生态源输入。

## 职责边界

```text
JS/WebView 接收用户交互
        ↓ 用户意图、轻量命令
Rust 处理业务，必要时调用 KMP 引擎
        ↓ JSON / typed chapter / media resource descriptor 通知
JS/WebView 读取最终资源并展示
```

| 层 | 职责 |
|---|---|
| JS/WebView | 接收交互、维护界面状态、读取已准备的资源、排版和展示。 |
| Rust | 承接全部业务状态的写入与中间业务：来源选择、请求和任务调度、引擎调用、存储、缓存、资源准备及变更通知。每份持久化或业务状态只有一个权威写入者。 |
| KMP 引擎 | 执行书源定义、规则和脚本；宿主能力经 Rust 协调。当前尚未接通的规则能力必须如实记录。 |

书源定义的权威文件保存在应用数据根目录 `sources.json`，导入、编辑、启停、搜索和备份恢复统一使用这个位置；`private-data` 只保存来源修订号等内部状态。书源管理界面可以收集用户输入，并通过 AppBootstrap 的 `sources` 资源读取包含原始定义字符串的不可变快照；可变的权威文件不直接通过 HTTP 发布。导入、校验和保存由 Rust 处理，原始 Legado 字段不会被应用资源 URL 校验或物化改写。Vue 不执行书源规则，KMP 仍是书源规则唯一执行端。其他展示页面只消费 Rust 发布的处理结果和资源。

各类状态的唯一权威归属如下：

| 状态 | 唯一权威 | 其他层的职责 |
|---|---|---|
| 页面、弹窗、选中项、滚动位置、临时输入、当前消费位置 | Vue | 维护当前界面交互；不复制 Rust 业务状态。 |
| 书架、任务、搜索执行状态、缓存状态、进度持久化、来源、资源、备份和业务事务 | Rust | 写入、协调并发布；Vue 提交意图并读取资源。 |
| 单次书源规则执行的内部状态 | KMP | 执行当前规则；Rust 负责调用、宿主能力、业务状态和结果发布。 |

JS 根据用户当前消费位置声明所需资源及预取范围；Rust 判断现有资源是否满足需求，并负责缓存命中、获取、恢复、去重、持久化及最终资源发布。Vue 不另存一份独立业务真相，也不负责协调 Rust 状态与异步生产者。

Rust 对已发布给 Vue 的每个资源版本提供不可变内容：发布 descriptor 后，该版本的内容不能被后续写入原位覆盖。刷新或替换先写完新版本并提交，再发布指向该版本的新 descriptor 和通知；已经持有旧 descriptor 的读取仍指向旧版本。章节 typed JSON 根据章节身份及最终正文 SHA-256 定位版本文件，不原地覆写；旧版本在当前进程内保留，启动恢复后回收不再被书籍引用的章节版本。私有媒体代理标识包含上游地址与请求头指纹，以免旧代理指向不同请求。稳定的 `resource://` 身份表示逻辑资源，不代表它的旧 descriptor 可以读到新内容。Rust 内部私有工作文件和事务 staging 可以修改；不可变约束从资源版本发布给 Vue 时开始。

资源 descriptor 必须自描述并定位所指的确切资源版本，包含可读取的 `src`、内容类型和媒体格式（包括 HLS）。前端不得猜 URL、拼路径、依赖 Resource Runtime 的 URL 结构或发送 HEAD 请求来推断格式；合法远程资源 URL 可按资源契约使用。事件只携带资源 descriptor；命令响应也不额外提供业务快照，让 Vue 在多个状态载荷间仲裁。资源正文和媒体通过 descriptor 消费，不作为常规 IPC 展示载荷。

异步搜索等生产者由 Rust 负责归属、取消/失效和结果发布。请求被取消或被新请求取代后，Rust 必须阻止迟到生产者发布旧结果；不能把 Vue 的代次比较当成业务正确性的最终仲裁。并发问题优先通过清晰的所有权、单写者和不可变发布解决。仅界面自身的临时异步交互可用局部取消或代次检查；搜索、任务、缓存等业务结果不得依赖 Vue 仲裁。

搜索是一次性操作。Rust 在本轮内存数组中累计并按书名、作者合并各来源结果；开始新搜索时丢弃上一轮累计结果及候选，不复用历史搜索缓存。每批需要更新界面时，只将包含本轮此前全部书目及本批新增来源的完整结果写入一个新的不可变 JSON 资源，写完再通知该版本的 descriptor；不反复写入私有搜索状态或逐条候选文件。每条合并书目保留默认候选的 `resultId` 等展示字段，并通过 `sources` 数组提供全部来源候选，各候选拥有独立 `resultId`，用于详情、入架及经 Rust 校验的换源。Vue 直接完整显示这些书目和候选，不按书名、作者再次合并，也不限制初始显示条数。展示 JSON 是临时资源版本，不纳入备份，已发布版本在本进程中保持可读，启动时回收。任务历史只保留状态；进程重启或备份恢复后清空结果，继续未完成搜索须从第一个来源重新搜索，同时保留已持久化的暂停、取消意图。

## 前端目录与页面导航

- `src/main.ts` 安装 Vue 应用和路由；`src/router/` 用哈希地址承载导航。每个页面路由直接加载对应的完整 Vue 页面；页面自行组合导航和所需共享组件。阅读器、弹窗和菜单属于当前会话的临时状态，不单独建路由。具体主导航和页面层级按产品原型校准。
- `src/main.ts` 直接挂载 `RouterView`，并分别挂载阅读器、外部导入、恢复状态和全局提示等独立 feature host；没有集中承载页面的 `App.vue` 壳。`src/features/<功能>/` 按业务收纳完整页面和专属状态，每屏自行读取所需资源并执行所属动作。Feature 通过窄的类型化 contract 协作，限制每个 feature 可依赖的状态与动作。`src/api/` 按 `books`、`sources`、`tasks`、`resources`、`settings` 等业务域提供统一 barrel API；不要求每个 feature 都建立 barrel。
- 拆分按职责和依赖边界进行，不按行数机械拆文件。新增 composable、转发层或共享 API 前，先明确它所属的业务域、公开 contract 及调用者真正需要的依赖；禁止用 `Record<string, any>` 或全量应用 context 转发绕过边界。
- `src/ui/` 仅放确实被多个功能复用的展示组件，例如二级页标题和统一返回按钮。新的抽象应消除已存在的重复，不为单次使用增加转发层。
- `src/style.css` 只放全局重置、颜色变量和通用控件；页面样式写在所属 Vue 的 scoped 样式中，页面之间不共享 CSS 级联规则。
- `src/api/` 是 JS 与 Tauri 命令、资源描述符之间的类型化接口。界面不直接访问 Rust 持久化文件，也不在 JS 侧重复业务规则。
- 中文注释说明模块职责、恢复边界和异步竞态等不直观约束；模板结构和显然的状态声明不逐行加注释。

页面拆分应让每个路由屏幕自行维护界面状态、加载资源并调用所属动作；入口只装配路由和独立 feature host，不集中拼装页面 props 或代替页面控制流程。跨层竞态先由 Rust 的状态所有者处理；仅界面自身的临时异步交互可以局部取消或使用代次检查，不用于搜索、任务或缓存等业务状态。保留阅读器资源释放逻辑。

## Rust 代码布局

`src-tauri/src` 按业务职责分目录，`lib.rs` 保留 crate 入口和稳定模块路径：

- `application/`：应用服务编排、任务生命周期和 Tauri 命令适配。
- `books/`、`shelf/`、`discovery/`、`rss/`：书籍导入与元数据、书架、首页来源分类与搜索、RSS 内容处理。
- `sources/`：KMP 书源引擎及其 HTTP、浏览器、JNI 和私有存储宿主能力。
- `resources/`、`backup/`、`models/`：资源交付、事务恢复、备份和持久化数据结构。
- `reading_tools/`、`search/`、`settings/`：阅读历史与规则、搜索历史和朗读配置。

较大的业务模块继续按独立职责拆到子模块；跨模块共享仅通过必要的可见性和 facade 导出，避免更改 IPC 命令名或资源数据契约。

## 存储和阅读

- 应用结构化状态使用 JSON：书架、书籍和目录索引、进度、设置、任务、书签、历史等。Rust 读写文件；JS 读取浏览器资源，不直接修改应用数据目录。
- 书架条目中的 `id` 是 `books/{id}` 书籍目录名；资源服务读取 `shelf.json` 时临时提供指向 `books/{id}/book.json` 的 `bookSrc` 浏览器地址，不将运行时地址写入磁盘。书架详情和离线阅读由 Vue 直接读取该资源，不为读取书籍 JSON 调用 Tauri 命令。
- 正文按内容语义缓存引擎处理后的数据：纯文本保存为 typed text JSON，安全富文本保存为 typed richText JSON；音频、视频和 PDF 只在结构化资源中描述可消费入口，二进制与媒体代理状态独立保存。旧式 HTML 章节缓存不再读取、恢复或写入，准备章节只接受有效 typed 正文；书源返回的 HTML 富文本、EPUB、RSS、词典及最终 WebView 显示 HTML 仍属正常功能。
- JSON 持久化稳定的 `resource://` 逻辑标识或合法远程 URL。运行时 Rust 为确切资源生成可读 `src` 并发布 descriptor；动态代理端口和 capability token 可用于运行时读取，但不写入长期数据。富文本中的本地资源 ref 由 Rust 物化，在线相对 URL 也必须在 Rust 发布前依据可信内容基址归一化；Vue 不从 localhost/resource 路径推导资源关系。
- Vue 根据明确的 `contentFormat` / typed resource 生成最终显示文档并应用字体、行距、主题和用户展示替换；不把显示变化写回缓存。书源自己的清理/替换由引擎执行，Rust 保存并发布其处理后的内容数据。
- 已准备资源的翻页、排版和切换由 JS 完成，无需每次经 Rust。JS 根据用户当前消费位置声明所需资源及预取范围；Rust 判断现有资源是否满足需求，并负责缓存命中、获取、恢复、去重、持久化及最终资源发布。
- 阅读进度在离开书籍、进入后台等可捕获的生命周期低频委托 Rust 持久化；不保证系统强杀会触发最后一次回调。
- 小说在首页、发现、搜索或书架打开时都使用同一份正式书籍 JSON、私有书源数据、目录和章节缓存。打开详情或阅读不会加入书架；只有明确的加入/移除操作改变书架成员。阅读进度照常写入书籍资源，只在书籍已入架时同步到书架条目。应用启动先完成恢复，再清理书架外 `book-*`/`local-*` 的书籍 JSON、进度和缓存，并保留 RSS 等非书籍资源。
- 删除、编辑书架和其他持久化变更也由 Rust 执行，返回资源入口并通知 JS 重读。
- 产品数据模型渐进采用带明确类型的 `Content` variants 覆盖小说、漫画、音频、视频和 RSS 等实际内容；公共字段只放跨类型真正共用的信息，类型特有字段由判别分支表达。Rust 应用边界负责将 KMP `Book`/`Chapter` 转换为应用契约；引擎内部保留现有模型，不要求迁移或同步改名。`Segment` 只表达真实存在的有序消费单元，不为单篇文章、电影等内容强造目录，也不把差异压进万能通用结构。

## 当前实现取舍

- KMP 执行书源，Rust 提供 HTTP、Cookie、存储和图片处理宿主。私有书源浏览器与展示 WebView 隔离：离线 DOM 快照禁止页面脚本和联网；桌面动态 GET 使用私有浏览器执行页面及有界异步规则。移动端动态页面、动态 POST 和资源嗅探仍未接通，不静默改为另一种请求。
- 网页登录由私有原生浏览器收集 Cookie，经 Rust 交给 KMP。展示前端只接收会话标识和状态；保存 Cookie 不等同于验证登录成功。会话同时校验来源修订号与运行时恢复代次，阻止旧会话覆盖恢复后的数据。
- HTTP TTS 配置保存在 ResourceStore 根目录 `http-tts.json`，由 Rust 校验和持久化；KMP 执行请求规则，Rust 将音频准备为浏览器资源。AppBootstrap 发布该配置的 resource descriptor，Vue 使用 `readResource` 读取完整配置并导出原始 JSON；手写、单条覆盖、本地/网络导入和删除统一通过配置变更命令写入，导入入口只负责取得 JSON，空 ID 表示新增/导入，已有 ID 表示覆盖单条配置，修改时保留应用内部 ID。显示替换规则的 descriptor 也由 AppBootstrap 发布，Vue 使用 `readResource` 读取 JSON，规则变更通过 Rust mutation command 写入并返回新 descriptor。临时音频与调试预览在启动时清理，不进入备份。
- 当前代码已完成搜索结果的 Rust 单写者、迟到生产者发布权校验和不可变搜索快照；路由页面由各自 Vue 组件直接组合，入口挂载路由与独立 feature host；ResourceDescriptor 也已成为 typed 资源的前端读取边界。仍需继续按真实调用边界收窄部分宽 composable，Rust 多个业务模块也仍共享较宽的 `ApplicationService`。文件拆分本身不代表低耦合完成；后续只按真实依赖继续收窄，不为追求文件长度新增转发层。
