# 内容库与分类缓存设计

本文记录本轮确定的内容库、缓存和搜索设计，不修改旧设计文档。代码按此结构实现；运行验收状态见文末。

## 目录结构

```text
内容库.json
cache/
├─ text/
│  ├─ t001/
│  │  ├─ t001.json
│  │  ├─ c001.txt
│  │  └─ c002.txt
│  └─ t002/
│     ├─ t002.json
│     └─ c001.txt
├─ html/
│  └─ h001/
│     ├─ h001.json
│     ├─ c001.html
│     ├─ c001.css
│     └─ c001_p001.webp
├─ image/
│  └─ i001/
│     ├─ i001.json
│     ├─ c001_p001.webp
│     └─ c001_p002.webp
├─ audio/
│  └─ a001/
│     ├─ a001.json
│     └─ c001.mp3
├─ video/
│  └─ v001/
│     ├─ v001.json
│     ├─ c001.mp4
│     ├─ c002.m3u8
│     └─ c002_s001.ts
└─ pdf/
   └─ p001/
      ├─ p001.json
      ├─ original.pdf
      └─ cover.webp
```

- `t001` 等名称只是示例，实际使用稳定的内容 ID。不同来源的内容分别拥有缓存 ID，不按书名共用缓存。
- 一个内容的完整信息、正文、图片、媒体、封面和导入原文件全部放在 `cache/{类型}/{id}/` 中，不再增加子目录。
- `text` 只保存纯文本；HTML 独立放在 `html` 类型中。HTML 内容的插图、样式、字体等依赖留在该 HTML 内容自己的目录中。
- 六种类型为 `text`、`html`、`image`、`audio`、`video`、`pdf`。类型由所在目录确定，不在每条预览里重复保存。
- 六种缓存类型不等于书源搜索类型。书源搜索只提供文本、音频、图片、视频四种选择，没有“全部”，也不提供 HTML、PDF 搜索选项。
- 搜索结果只保存在当前会话内存中，不创建搜索缓存目录或结果文件。
- 一个内容使用一个目录类型。需要 HTML 排版的内容按 HTML 保存，PDF 按整份文档保存，不混入文本目录。
- 其他独立应用数据不在本文中重新设计。

## 内容库与缓存的边界

`内容库.json` 只包含已经加入内容库的条目。存在缓存不代表属于内容库；搜索、打开、预加载不得自动添加内容库成员。

完整信息以 `cache/{类型}/{id}/{id}.json` 为准。内容库中的信息是列表预览快照，不是详情或阅读所需的完整对象。

- 加入内容库：从完整信息提取预览，加入对应类型数组。
- 移出内容库：移除预览及分组中的引用，保留缓存目录和完整信息。
- 更新完整信息：只刷新已经存在的预览，不把未加入的缓存补进内容库。
- 打开详情、阅读或播放：读取完整信息，不能拿预览代替。
- 删除分组：只删除分组定义，不删除条目或缓存。
- 删除缓存内容：根据明确的删除操作清理目录；如果它仍在内容库中，同时移除预览和分组引用。

预览字段方案：

六种类型使用同一套预览字段，均支持作者、封面、最新标题和最近阅读时间。只有原始信息或阅读记录实际缺失时，才省略对应字段，不能仅因类型不同就省略。示例 PDF 没有来源提供的最新章节信息，因此省略 `latest`。

| 字段 | 含义 |
|---|---|
| `id` | 内容 ID，必填 |
| `title` | 显示名称，必填 |
| `author` | 作者或创作者，可选 |
| `cover` | 封面远程地址或相对本内容目录的文件名，可选 |
| `total` | 可选；PDF 为文档页数，其他类型为可阅读目录条目数，卷标题等不计入 |
| `latest` | 最新可阅读章节、话或集的标题，可选 |
| `read` | 当前可阅读目录条目的序号；PDF 为文档页码。均从 1 开始，可选 |
| `readAt` | 最近阅读时间，Unix 秒，可选 |
| `updatedAt` | 可选扩展；需要显示更新日期或按更新排序时，保存目录内容变更时间，Unix 秒 |

- 不在预览里保存 `sourceId`、完整目录、简介、请求信息、精确阅读位置或缓存清单。
- 无意义的空值和空数组省略；没有内容的类型可以省略。读取缺失的类型或 `groups` 时按空列表处理。
- `groups` 数组顺序决定分组顺序；分组的 `id` 数组顺序决定组内条目顺序。
- 各类型数组顺序决定该类型的手动顺序。
- 分组可以混合类型，同一内容可属于多个分组。内容 ID 必须在所有类型中唯一。
- 未出现在任何组中的内容库条目是未分组；“全部”“未分组”由界面生成，不持久化。
- 分组不能引用内容库之外的缓存 ID。

## 完整信息 `{id}.json`

每个内容只使用这一份完整信息文件，不再拆出 `book.json`、目录 JSON、私有状态 JSON 或每章节的包装 JSON。实际正文和媒体保存为独立内容文件。

### 公共字段

| 字段 | 保存内容 |
|---|---|
| `id` | 内容 ID，用于核对文件和请求身份 |
| `title`、`author`、`intro`、`cover` | 完整显示资料，封面可以是远程地址或同目录文件名 |
| `tags`、`status` | 可选题材标签、连载状态；不用于判断阅读器类型 |
| `sourceId` | 可选来源 ID，本地导入可省略 |
| `engine` | 可选原始书籍解析数据和规则变量；保留引擎执行所需字段，不向 WebView 发布 |
| `alternatives` | 未缓存或已缓存的换源候选资料，包含 UI 展示字段及 Rust 私有解析参数，不以内容 ID 代替 |
| `original` | 可选导入原文件的同目录文件名 |
| `url` | PDF 等整文件内容的实际入口；章节式内容的入口放在各章节中 |
| `updatedAtMs` | 可选目录内容变更时间，Unix 毫秒；单纯检查更新不推进此时间 |
| `progress` | 精确阅读位置和最近阅读时间 |
| `chapters` | 有序目录及每个目录条目的资源索引 |

不存在内容库成员标志、收藏标志或分组字段。即使没有加入内容库，这份完整信息仍可独立打开、刷新和继续阅读。

目录顺序使用数组顺序，不再重复写章节序号。章节使用稳定 ID，插入或移动章节不改变已有 ID；卷标题条目使用 `volume: true`，没有正文资源。

章节字段直接平铺：`engineurl` 保存书源规则使用的章节解析入口，`url` 保存实际内容地址。`url` 可以是当前内容目录内的文件名，也可以是尚未缓存的远程资源地址。不再使用章节级 `engine`、`resource` 包装，不单独保存 `file`，也不重复写目录已经确定的内容类型。

引擎执行仍需保留规则 URL 的原始选项和必要的章节变量；`engineurl` 不能因为显示规范化而丢掉执行参数。其他必需执行字段根据实际调用契约补充，不新增与显示数据重复的包装对象。

### 换源候选 `alternatives`

候选来源还没有建立自己的缓存时，也必须能够展示和继续解析。因此 `alternatives` 保存候选对象，不保存内容 ID 列表，不为每个候选创建独立的完整信息文件。

| 字段 | 职责 |
|---|---|
| `sourceId`、`sourceName` | 来源关联与来源名称，供显示和选择 |
| `title`、`author`、`cover`、`latest` | 该来源的实际展示资料；有需要时可补充已有简介等字段 |
| `engineurl` | Rust 私有的内容详情解析入口，完整保留源规则所需的 URL 选项 |
| `engine` | Rust 私有的原始书籍参数和规则变量，不能只保存展示字段后丢失执行上下文 |

- 字段平铺，展示资料不另包 `ui` 对象。`engine` 只保留确有必要的原始执行数据，不是再包装一个 `url`。
- 由候选的 `engineurl` 还原引擎需要的 `bookUrl`；其他原始字段按执行契约保留。执行时不以用户修改的显示资料覆盖原始规则参数。
- Rust 从当前 `{id}.json` 生成公开候选列表，过滤 `engineurl`、`engine` 及其他私有参数；不把磁盘完整候选对象原样送给 UI。
- UI 选择候选后提交当前内容标识、候选位置及所选来源关联，Rust 读取当前完整信息并核对候选，不能把不存在的缓存 ID 当作换源入口。
- 候选按来源和来源内内容定位去重；不以书名、临时数组顺序或未建立的内容缓存 ID 判断来源身份。
- 真正切换到该候选时，再复用已有目标缓存或解析并生成目标 `{id}.json`。新内容保存其余换源候选资料，不批量生成其他候选文件。
- 候选资料保存在当前内容文件中，搜索会话释放后仍可显示和换源。

文本章节只引用纯文本文件。正文不嵌入 JSON，HTML 使用独立类型。

### HTML 章节

完整信息文件为 `cache/html/h001/h001.json`，公共资料字段与其他类型一致。章节直接引用同目录 HTML 文件：

```json
{
  "id": "c001",
  "title": "第一章",
  "engineurl": "https://example.org/html/1/chapter/1",
  "url": "c001.html",
  "files": ["c001.css", "c001_p001.webp"]
}
```

`files` 列出本章节使用的本地依赖，供清理和离线完整性检查使用。HTML 及其图片、样式、字体全部平铺在该内容自己的目录中，引用在保存时改为可正确读取的同目录资源。`html` 目录已经确定正文类型，不再保存重复的 `format` 字段。

### 图片章节

图片页直接放在章节的 `pages` 数组中；它是有序图片列表，不另包一层资源对象，不另存章节 JSON。

```json
{
  "id": "c001",
  "title": "第一话",
  "engineurl": "https://example.org/comic/1/chapter/1",
  "pages": [
    {
      "id": "p001",
      "url": "c001_p001.webp"
    },
    {
      "id": "p002",
      "url": "https://example.org/images/2.webp"
    }
  ]
}
```

`pages` 顺序就是阅读顺序。第一页已经缓存；第二页仅解析到远程地址。页 ID 稳定，供阅读进度定位。漫画直接消费图片列表，不拼成小说正文或 HTML。

### 音频章节

```json
{
  "id": "c001",
  "title": "第一集",
  "engineurl": "https://example.org/audio/1/chapter/1",
  "url": "c001.mp3",
  "durationMs": 1800000
}
```

`url` 是当前实际播放地址：已缓存时引用本地文件，未缓存时引用解析后的远程资源。直接文件与流媒体的播放信息由 Rust 在资源解析或读取时提供；不能要求前端靠远程 URL 后缀猜测。时长未知时省略 `durationMs`。

### 视频章节

```json
{
  "id": "c001",
  "title": "第一集",
  "engineurl": "https://example.org/video/1/chapter/1",
  "sources": [
    {
      "id": "720p",
      "label": "720P",
      "url": "c001_720p.mp4"
    },
    {
      "id": "1080p",
      "label": "1080P",
      "url": "c001_1080p.m3u8",
      "files": ["c001_1080p_s001.ts", "c001_1080p_s002.ts"]
    }
  ]
}
```

视频档位顺序使用 `sources` 数组顺序；清晰度选择放在精确进度的 `quality` 字段，值对应档位 ID，不在各档位重复存 `selected`。

HLS 的 `files` 列出主入口之外的所有本地依赖，包括子播放列表、分片、初始化段和必要密钥。只有下载完整并把播放列表引用改为本地文件后，才把 `url` 更新为本地入口。实际文件全部平铺在当前内容目录中。

媒体和图片按需保存请求头等私有请求信息，但不复制书源级 Cookie 或登录凭据到每个资源。公共书源身份仍由现有引擎登录状态提供。

### PDF 完整信息

PDF 独立使用 `cache/pdf/p001/p001.json`。文档入口只保存一次；目录是可选书签大纲，不把每页拆成正文缓存。

```json
{
  "id": "p001",
  "title": "PDF 文档名称",
  "author": "作者",
  "intro": "完整简介",
  "cover": "cover.webp",
  "url": "original.pdf",
  "pageCount": 320,
  "progress": {
    "page": 12,
    "updatedAtMs": 1791800600000
  },
  "chapters": [
    { "id": "c001", "title": "第一章", "page": 1 },
    { "id": "c002", "title": "第二章", "page": 25 }
  ]
}
```

页码从 1 开始。PDF 的 `url` 引用文档原文件，因此不再重复写一个指向同文件的 `original` 字段；清理可再生成缓存时保留该原文件。PDF 原生书签的子级结构和精确页面坐标如需保存，按原始大纲和目标信息扩展，不强制丢成只有一级的目录。没有大纲时省略 `chapters`。

### 精确进度

所有进度保存 `updatedAtMs`；章节式内容使用稳定的 `chapterId`，位置按类型表达：

- 文本：`charOffset`。按内容字符定位，不保存受字体和窗口尺寸影响的分页页码。
- HTML：稳定段落 `anchor` 与段落内 `charOffset`，按内容位置定位。
- 图片：`pageId`、`offsetRatio`。比例表示该图片内的阅读位置，不保存窗口相关的整章滚动像素。
- 音频：`timeMs`。
- 视频：`timeMs`，可选 `quality` 表示选中的视频档位 ID。
- PDF：`page`，文档页码从 1 开始；必要时增加页内阅读位置。没有章节时不要求 `chapterId`。

章节式内容不同时保存可从章节 ID 查出的章节序号。内容库的 `read` 从完整目录和当前章节 ID 生成；PDF 的 `read` 直接取文档页码。完整时间转换为秒生成预览 `readAt`。

## 资源读取、写入与清理

- 本地文件引用都是相对当前内容目录的文件名，不保存绝对路径、运行时端口或 localhost 地址。文件名必须限制在当前目录内。
- `engineurl`、远程资源地址、原始书籍 `engine` 和必要请求头由 Rust 管理；不能把包含私有数据的完整 JSON 原样通过静态服务发布。Rust 读取同一文件后生成公开响应，过滤私有执行参数并把 `url` 转为运行时可读取地址，不另写公开副本。
- 文本、HTML、图片、音频、视频、PDF 由当前目录类型确定，分别交给对应内容组件。直接媒体与 HLS 的实际播放方式由 Rust 提供运行时信息，不重复持久化内容类型，前端不靠远程 URL 猜测。
- 解析出 URL、注册代理、开始下载都不等于已经缓存。`url` 只有在下载完成并校验通过后，才能改为本地文件名；读取时仍需处理文件丢失。
- 大文件下载、解析使用临时文件，完成后再发布文件和索引。未完成下载不能覆盖现有可用版本。
- 目录刷新按稳定章节 ID 合并，保留仍有效的缓存和进度，拒绝已经过期的异步结果。
- 修改完整信息后刷新现有预览；跨文件写入使用可恢复事务。恢复预览时不能通过扫描缓存目录重新创建内容库成员。
- 清理可再取得的正文或媒体时，同时移除相应本地 `url` 和依赖文件引用，保留 `engineurl` 以便重新解析；保留完整资料、来源目录和进度。导入原文件不是可随意删除的缓存副本。
- 临时签名 URL 失效时重新解析，不影响已有完整本地文件。仅有旧地址不能保证可继续在线播放。
- JSON 落盘紧凑序列化，省略缺失的可选字段和无意义的空集合。
- 备份需分别表达“内容库成员”与“已有缓存”，不能在恢复时把所有缓存加入内容库。

## 搜索

搜索结果只保存在内存中，不落盘，不写入 `内容库.json`。一个搜索任务 ID 标识一次关键词、来源范围和筛选条件确定的搜索会话；新搜索使用新任务 ID，分页结果合并到当前会话。

搜索必须先选择一种源类型：文本、音频、图片或视频。没有“全部”，不能一次调用混合类型的书源。Rust 按请求类型筛选当前启用来源，再与用户指定来源范围取交集；没有匹配来源时返回无可用来源，不能扩大到其他类型。

源类型对应现有 `bookSourceType`：文本为 `0`、音频为 `1`、图片为 `2`、视频为 `4`，其他类型不参与这四类搜索。前端只展示同类型可选源，Rust 同样校验，不能仅依赖界面过滤。

一次任务中的结果已确定搜索类型，结果批次不再按六种缓存类型包一层分类。书名和作者匹配的来源候选合并展示；不同类型的任务互不混入。搜索候选使用任务内的临时标识供 IPC 选择，不表示它已经有内容缓存。

### IPC 数据契约

搜索通过 Tauri IPC 传输结构化对象。Rust 使用可序列化结构，Vue 使用对应 TypeScript 类型；序列化和反序列化由 Tauri 完成。应用层不先把结果变成 JSON 字符串，不让前端再次 `JSON.parse`，不返回搜索快照文件地址。

前端通过 `invoke` 提交选定源类型、关键词、分页和可选来源范围，取得任务 ID；结果通过 Tauri `Channel<SearchBatch>` 按来源或分页批次发送，界面按当前任务、书名、作者和候选标识合并。代码使用每个任务自己的 IPC 通道；不再发布搜索快照文件。

归一化的界面类型如下；这些对象不落盘：

```typescript
type SearchType = "text" | "audio" | "image" | "video";

interface SearchRequest {
  sourceType: SearchType;
  keyword: string;
  page: number;
  sourceIds: string[];
}

interface SearchCandidate {
  resultId: string;
  sourceId: string;
  sourceName: string;
  title: string;
  author?: string;
  coverSrc?: string;
  latestChapter?: string;
}

interface SearchResult extends SearchCandidate {
  sources?: SearchCandidate[];
}

interface SearchBatch {
  taskId: string;
  incremental: true;
  results: SearchResult[];
  status?: "queued" | "running" | "paused" | "completed" | "cancelled" | "failed";
  completedSources?: number;
  totalSources?: number;
  complete?: boolean;
  errors?: Array<{ sourceId?: string; message: string }>;
  error?: string;
}
```

- 搜索类型在启动参数中明确指定，不支持 `all`、`html`、`pdf`，每批直接传结果数组，不重复类型字段或分类对象。每批只传新增或更新的结果，不反复传整个累计列表；没有新增结果的批次使用空 `results` 数组。
- 搜索类型、关键词、请求页和来源范围属于启动参数及当前任务状态，不在每批结果中重复发送。没有命中的来源也保留在 Rust 的任务范围中。
- 分组显示默认候选的资料；`sources` 保留各来源自己的展示资料，不覆盖另一来源的标题、封面和最新章节。执行对象和详情解析地址仅在 Rust 内存中保留。
- 结果分组没有虚构的内容缓存 ID。`resultId` 仅用于任务内定位；点开并建立缓存后才产生或取得内容 ID，一个分组不能共用一个缓存目录。
- 候选的 `sourceId` 用来显示来源和继续执行解析，来源名称从现有书源列表取得。这与纯预览的内容库不同，搜索候选不能删掉执行所需的来源关联。
- 候选的 `engineurl` 是内容详情解析入口，由 Rust 保留在任务内存中，不是界面显示所必需的字段，不随每批预览发送。完整信息中的章节 `engineurl` 才是具体章节解析入口。
- 搜索返回的必要原始执行字段和变量由 Rust 留在当前任务内存中，供点开候选继续解析；发送给界面的结果过滤私有执行参数，不建立搜索数据文件。
- 任务进度、取消状态和各来源错误由当前搜索任务提供，不需要在每条结果中重复保存；结果批次只按需携带结束标志和错误信息。
- 分页按来源与来源内内容定位去重，保留已有候选标识；不同搜索会话和不同类型任务的异步结果不能混写。来源修改或删除后，旧候选必须重新验证再执行。
- 点开结果时通过 IPC 提交 `resultId`，Rust 通过候选绑定的任务，从内存取得原始解析参数并验证身份；界面不回传原始执行对象作为解析依据。结果对象本身不能代替仍有效的任务上下文。

### 点开、换源和加入内容库

1. 搜索命中时只更新内存结果，不创建内容缓存，不下载正文或媒体。
2. 点开结果时选择具体来源，复用已有完整信息或取得该来源的资料和目录，只写当前内容的 `cache/{缓存类型}/{内容ID}/{内容ID}.json`，不因此缓存正文、图片、音视频或封面文件。
3. 将同组其他来源的展示资料和私有解析参数写入当前文件的 `alternatives`。不请求其他来源的完整目录，不为候选创建独立 JSON 或缓存目录。
4. 实际切换来源时才生成或复用目标内容的完整信息 JSON，换源候选依靠保存的资料和执行参数继续解析，不依赖旧搜索会话，也不依赖尚不存在的内容缓存 ID。
5. 搜索按四种源类型执行，存储和阅读按六种缓存类型处理。HTML、PDF 是缓存与阅读类型，不是新增的书源搜索选项；详情阶段不能为了探测格式预取正文。阅读资源准备时按实际格式提供对应内容，尤其不能把图片 URL 当成文本展示。
6. 用户执行加入内容库时才生成预览；点开、阅读、换源都不自动加入。已在内容库中的条目更新预览，但不重复增加。

`chapters` 缺失表示目录未加载，空数组表示目录已经加载但没有条目。内容缓存生成后，可通过其中的来源定位独立补齐数据，不依赖搜索任务继续存在。

### 结果生命周期与搜索历史

结果在当前搜索会话内保留；切换关键词、清空搜索或结束会话时取消旧任务并释放内存。打开详情再返回搜索时，可以在同一会话中保留结果。释放结果不删除已经生成的内容缓存，不修改内容库成员或分组。

搜索历史只记录关键词、时间和必要搜索条件，继续归入历史数据，不保存整份结果或充当来源解析索引。应用重启不恢复旧搜索结果，重新执行搜索。

### 本地搜索

- 内容库列表筛选直接使用预览，结果仅在内存中，不遍历所有正文。
- 查找已有缓存内容时，只读取当前选定缓存类型范围内的内容信息文件；命中未加入内容库的缓存也不自动加入，不默认遍历所有类型。
- 正文搜索读取实际缓存文件。HTML 按可读文本搜索；图片、音频、视频只搜索资料和目录，不能把图片 URL、播放地址当成正文。PDF 正文搜索使用文档文字层。

## 全局状态与实现边界

Vue 使用导出的全局响应式状态：`contentLibrary` 保存内容库预览和分组，`openedBook` 保存当前完整内容，`searchResults` 等保存当前搜索会话。各页面引用同一份状态；旧页面需要的位置视图通过计算属性生成，不额外落盘。

Rust 使用同一个受管理的 `ApplicationService` 和共享 `ResourceStore`。持久化、源类型校验、源引擎执行、媒体请求头、任务控制和缓存写入由 Rust 负责。完整信息文件包含私有执行资料，HTTP 返回给 Vue 的内容视图过滤私有字段；没有新增 `static mut`。

代码已接入六种缓存目录、原生正文文件、图片页列表、音视频播放信息、PDF 页视图、阅读位置、备份和缓存清理。详情入口仅保存选中内容的完整 JSON 和 `alternatives`；只有显式下载任务才下载媒体、图片及 HLS 依赖。HLS 离线下载要求完整的有限播放列表，单个下载资源上限为 512 MiB。

实际 IPC 使用 `resultId` 定位内存候选，它不是内容 ID。搜索通过 Tauri `Channel` 增量回传结构化对象，候选任务通过 `get_search_task_results` 读取内存结果。私有 `bookUrl`、执行对象和请求头不进入这些响应。分页合并和会话释放均受当前任务身份约束。

完整 JSON 中额外的执行上下文保存在 `engineState`；持久媒体代理映射保存在同一文件的私有 `media` 字典中，条目只有 `url` 和可选请求头对象，不另建映射文件。运行时章节资源描述符、页序号、内容类型、目录总数和最新标题由 Rust 生成，不写回完整 JSON。PDF 进度只保存页码；文本字符位置按界面的 UTF-16 字符索引保存，HTML 同时保存段落锚点，图片保存页 ID 和页内比例，音视频保存时间，视频还可保存清晰度。

本轮按要求不编译、不启动程序，只做静态语法、引用、路径和差异检查。设备上的阅读、播放、下载及恢复效果仍需运行验收。旧 `shelf.json` / `books` 数据的自动迁移未加入；本轮没有读取、删除或改写已安装程序的数据。
